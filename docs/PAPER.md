# The PACT architecture

## From Agent Instructions to Executable Procedures: The PACT Architecture

Noah Dylan Pelegrini · Independent Researcher

[Read the manuscript](papers/PACT_From_Instructions_to_Procedures.pdf)

PACT treats procedures as reusable artifacts. Skills assemble capabilities; named state carries their information; bindings select executable mechanisms separately from the procedure. The architectural argument begins with these composition boundaries and then derives runtime responsibilities: scheduling dependencies, resolving services, mapping state, applying policies and exposing traces.

The reported two-task evaluation found greater elapsed time for structured execution, with intermediate artifacts and reusable components exposed. Text-output variability was slightly higher. The evaluation does not measure semantic accuracy and does not isolate runtime overhead from additional model invocations. No new experimental run is claimed.
